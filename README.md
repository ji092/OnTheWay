# 가는 길에 (On The Way)

"내 주변"이 아니라 **"내가 지나갈 경로"** 기준으로 경유지를 찾는 웹앱입니다.

내비게이션을 대체하지 않습니다. 경유지를 찾는 것까지만 담당하고, 길안내는 네이버맵으로 넘깁니다.

## 해결하는 문제

기존 내비의 장소 검색은 목적지 검색과 내 주변 검색뿐입니다. 그래서 검색 결과가

- 지금 가는 경로 위에 있는지 알 수 없고
- 진행 방향 반대편이라 유턴이 필요한 곳이 섞여 나오고
- 경로에서 얼마나 벗어나는지, 몇 분이 더 걸리는지 모릅니다

이 앱은 출발지에서 목적지까지의 **경로 자체를 검색 대상**으로 삼고, 이탈거리·추가 시간·유턴 여부를 숫자로 보여줍니다.

## 주요 기능

- **경로 기반 검색** — 경로 폴리라인을 일정 간격으로 샘플링해 각 지점에서 반경 검색. 응답이 상한을 넘으면 원을 4분할해 재귀 수집
- **진행 방향 판별** — 진행 벡터와 대상 벡터의 외적 부호로 좌/우를 계산해 유턴 필요 여부를 근사 판별. 급커브 구간은 판정 보류
- **추가 시간 / 거리** — 전체 후보는 근사치, 상위 3개는 경유지 길찾기로 실측
- **고급유 카테고리** — 지도 API로는 취급 유종을 알 수 없어 유가정보 API를 별도 연동. 고급휘발유 취급 주유소만 필터링하고 리터당 판매가격까지 표시
- **조건 필터** — 이탈 허용 거리(100/300/500m), 유턴 제외, 들르는 위치(출발지 근처/목적지 근처). 모두 서버 재호출 없이 클라이언트에서 재필터링
- **길안내 핸드오프** — 선택한 경유지를 네이버맵 URL 스킴으로 전달. 앱 미설치 시 스토어 폴백
- **PWA** — 홈 화면 설치, 오프라인 폴백

### 환경변수

저장소 루트에 `.env.local`을 만들고 아래 이름으로 값을 채웁니다. 값은 저장소에 두지 않습니다.

| 이름 | 용도 | 노출 범위 |
|---|---|---|
| `KAKAO_REST_KEY` | 장소 검색, 길찾기 | 서버 전용 |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | 지도 SDK | 브라우저 노출 — 콘솔에서 도메인 제한 필수 |
| `OPINET_API_KEY` | 유가 정보 | 서버 전용 |
| `KAKAO_DAILY_BUDGET` | 일일 호출 예산 (선택, 기본 500) | 서버 전용 |
| `OPINET_DAILY_BUDGET` | 일일 호출 예산 (선택, 기본 1200) | 서버 전용 |

지도가 뜨지 않으면 카카오 개발자 콘솔 플랫폼 설정에 해당 도메인(`localhost` 포함)이 등록됐는지 확인하세요.

## API

모든 외부 API 호출은 서버에서만 이뤄집니다. 클라이언트는 지도 SDK 외에 외부를 직접 호출하지 않습니다.

| Method | Path | 목적 |
|---|---|---|
| POST | `/api/route` | 출발/도착 좌표 → 경로 ID + 좌표열 + 소요시간/거리 |
| POST | `/api/search` | 경로 ID + 카테고리 → 후보 배열 |
| POST | `/api/extra-time` | 상위 3개 정밀 추가시간/거리 |
| GET | `/api/place-search` | 지명 자동완성 |
| GET | `/api/health` | 호출 계측, 일일 예산, 캐시 크기 |

오류는 경로 없음(422) / 외부 API 실패(502) / 내부 오류(500)로 분리해 응답합니다. 코드 버그가 "경로를 찾을 수 없습니다"로 위장되지 않도록 하기 위함입니다.

## 설계 메모

**저장하는 데이터가 없습니다.** 지도 API의 POI는 약관상 영속 저장이 금지되고, 좌표와 검색어는 개인 위치정보라 서버에 남기지 않기로 했습니다. 계정 기능도 없습니다. 결과적으로 DB가 필요 없어 전부 걷어냈고, 인메모리 TTL 캐시(10분)만 씁니다.

**쿼터 보호를 다층으로 뒀습니다.** 검색 한 번에 외부 API를 최대 9회 호출하고 전체 탭은 그 배수입니다. 그래서 (1) 경로 ID + 키워드 캐시로 같은 조건 재검색 시 외부 호출을 0으로 만들고, (2) IP 단위 슬라이딩 윈도우 레이트리밋을 걸고, (3) 외부 API를 호출하는 단일 길목에서 일일 예산을 차감합니다. 재시도도 예산을 소모하므로 시도마다 차감합니다.

로그인으로 막는 방법도 검토했지만, 로그인은 "누가 들어오는가"를 막는 것이고 쿼터는 "얼마나 부르는가"의 문제라 해결되지 않습니다.

**외부 호출은 타임아웃·재시도·폴백을 한 계층에서 일원화했습니다.** 시도별 타임아웃만 걸면 (타임아웃 × 시도 수 + 백오프)만큼 매달릴 수 있어 서버리스 실행 한도를 넘길 수 있습니다. 그래서 작업 전체 예산(7초)을 두고, 남은 시간 안에 끝낼 수 없는 재시도는 하지 않습니다.

**추천 점수 가중치는 실측으로 조정했습니다.** 시간 40% + 거리 30% + 방향 30% 가중합입니다. 처음에는 시간에 50%를 뒀는데, 정규화 상한(10분)이 실제 값 범위(1.2~3.0분)와 맞지 않아 시간 축의 실효 변별력이 명시 가중치의 12%밖에 되지 않았습니다. 상한을 5분으로 낮추고 비율을 조정했습니다.

## 알려진 한계

- 캐시, 호출 카운터, 레이트리밋이 모두 프로세스 메모리 기반입니다. 서버리스라 인스턴스가 여러 개면 각각 따로 셉니다. 정확한 전역 제한이 필요하면 공유 저장소가 필요합니다
- 대중교통 경로는 국내 지도 API가 REST로 제공하지 않아 카드만 두고 비활성 처리했습니다
- 영업시간·24시간 여부는 무료 API에 데이터가 없어 넣지 않았습니다
- 현재 위치 자동 입력(GPS)은 미구현이라 출발지도 직접 검색해야 합니다
- 방향 판별은 정밀 도로 링크 데이터 없이 계산한 근사치입니다
